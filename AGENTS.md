# Repository Guidelines

atmos is a production-grade Go library for the AT Protocol, favoring correctness, robustness, and performance.

## Build, Test, and Development Commands

Run `just --list` to find the available commands and their documentation. Read the `justfile` when more information is needed.

Prefer using `just` rather than plain `go` invocations.

## Coding Style & Naming Conventions

Exported names need doc comments; package docs go in `doc.go`.

Prefer `%w` error wrapping. Handle all errors gracefully and correctly.

See our aggressive linter config in `.golangci.yaml`.

## Generated Code & Lexicons

Files under `api/` begin with `// Code generated by lexgen. DO NOT EDIT.` Never hand-edit them. Change `lexgen/` and the pinned schemas, then run `just lexgen`. `lexgen.lock` records upstream commits.

## Testing Guidelines

Tests use `stretchr/testify` (`require` preferred) with `t.Run` subtests and `t.Parallel()` where independent. Name tests `TestXxx` and fuzz targets `FuzzXxx`. Every behavioral change needs a test that fails without it, and performance-sensitive paths need benchmarks. Run `just && just test-race` before submitting.

We test in-depth to attempt to surface hard-to-find bugs before they go in to production. Unit tests have some value, but we also do integration testing, swarm testing, end to end testing, fuzz testing, performance benchmarks, and more.

## Security & Configuration Tips

`.github/workflows/ci.yml` pins actions to SHAs, blocks egress, and disables caching by design — read its header before changing it. Do not interpolate untrusted event fields into `run:` steps.
